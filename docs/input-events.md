# 输入分发与练习修正

键盘和鼠标原生钩子均以单例注册，Start 对已有句柄直接返回。模块不会独立安装钩子。

原生回调只解码并投递到共享 InputEventDispatcher；移动和滚轮仍在原生回调里做轻量累加。分发器按顺序分批向模块发送事件，每次最多 128 个投递，模块异常独立记录，不阻断其他模块。键盘统计、练习、动画分别订阅所需事件，退出时解除订阅并停止自己的定时器。

KeyDatabaseService 和 ClickDatabaseService 的保存入口只入队，BackgroundBatchWriter 在后台每 25ms 收集最多 256 项，以事务提交。队列有界（8192）：满时丢新条目并计数告警，入队方绝不被阻塞。重试以完整事务为单位，最多 3 次，之后丢弃本批并记 ERROR；异常不回抛给入队方，worker 也不会因连续失败而停摆。两个库均为 journal_mode=WAL，写连接带 busy_timeout=5000，因为词频会另开只读连接反复扫 KeyPressRecords，写与读是真并发。正常退出停止输入、排空已接收事件，并等待末批数据写完（含已从队列取出、正在退避重试的在途批次）；异常终止仍可能丢失尚在内存中的极短批次。词频只从已提交按键记录增量更新，避免两套组词逻辑。

落库队列的实测数据（真库副本、接真实 WordFrequencyStore 并发扫描）：入队 6000 条 3 ms，Flush 776 ms，读侧锁异常 0 次；队满时 5000 次入队 0 ms，丢弃 4900 + 写入 100 = 5000 有条可查；同一压力下未开 WAL 的对照组也不丢数据，WAL 的收益体现在延迟上（满载扫描时最长单批 108 ms 降到 18 ms），不是正确性证据。

练习输入按正文格数逐键落子，光标推到正文末尾后多余的键直接忽略；退格退回上一子的落点，按住退格可重复退回。落子模型下不存在“追不上正文”的堆积：错键只计错不占正文，正文长度也不再需要输入上限。清空按钮只清掉当前输入、高亮和错误状态，不换题，不撤销已经发放的成绩，也不会让同一句重复获分。按钮不获取键盘焦点，避免下一次回车再次激活清空。

验证：Release/Debug 编译通过；16 项验证覆盖真实原生回调到事件队列的隔离、Shift 标点、重复退格、模块故障隔离、顺序分发、后台批处理及独立 SQLite 的退出刷盘。深浅主题 WPF 渲染检查完成。未启动真实全局钩子采集用户输入，未测量整程序实际启动时间。

检查了项目 .vs、Debug 输出、XAssistant_Dev 应用数据目录及相关临时转储路径，未发现性能录制/内存转储缓存。普通索引、用户设置及统计数据库予以保留。
