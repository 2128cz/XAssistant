# 词频投影

数据流：键盘钩子 `KeyPressed` → 原有 `KeyCounterViewModel` → `key_data.db/KeyPressRecords` → `WordFrequencyStore` → 词频面板。复用已落盘的钩子记录，不再额外记录一份输入；实时增量和历史恢复遵循同一套规则。

## 规则

- 单个英文字母、数字与数字小键盘别名（如 `Num 7`、`NumPad7`）连续组成词，字母统一小写。
- 除退格外，其他按键均为分隔符，包括空格、标点、Tab、Enter 和修饰键。这里按物理按键统计，不按 Shift 后的屏幕字符统计。
- 退格删除最近一个字符；删除词间分隔符时可重新打开上一个词，撤销旧词频。修正后的词遇分隔符再计数。连续删除整词、删除多个分隔符和跨重启继续组词均可回放。
- 未结束的词只显示当前片段，不提前加入词频。修正次数归于最后完成的词，不把中途错误拼写当作额外词频。“易错”筛选显示有过退格修正的词；这只是候选，不自动判错或打赞踩标记。
- 本规则根据按键序列推导，不解析编辑器的选区、光标位置、撤销、粘贴或输入法最终上屏内容。

## 持久化与恢复

三个数据库均位于原应用数据目录（Debug 使用 XAssistant_Dev）：

- `key_data.db`：现有原始记录，只读回放，不修改或删除。
- `word_frequency.db`：可重建投影。Fragments 保存按顺序完成的词及可回退片段；Totals 保存词频、退格次数与发生修正的词次数；State 保存最后处理的原始记录 ID 和时间；Batches 保存每批的 ID 范围、时间范围及记录数。
- `word_marks.db`：独立保存人工赞踩，1 为绿、-1 为红、0 为未标记。重建词频不影响它；如果标记库本身丢失，原始按键无法恢复人工判断。

每两秒检查新增记录，每批最多 2000 条，在后台处理；批与批之间让出约两倍的处理时间，回灌途中词频列表每秒最多重建一次，避免与热力图、输入节奏曲线的定时器争抢主线程。片段、频次、批次摘要与游标在同一 SQLite 事务提交。重启从游标继续，未完成词也保留。原始记录按自增 ID 排序，时间只作展示与摘要边界，避免同一时间戳重复或系统时钟回拨造成漏算；游标同时记下已统计到的原始时间戳，下次只读它之后的记录，统计过的不重复统计。

词频库缺失时自动创建，但冷缓存只回灌最近 3 天：未统计历史跨度超过 3 天时，游标直接推到窗口起点并同步该行的校验锚点，更早的历史不进自动统计。此时右侧按钮写成「统计 量级 · 约 预估」，点它才从第一条重放；已有缓存则不受此限制，照常从游标续算。按钮也可随时重新回放。每批校验游标对应原始记录，源日志被替换或截断时重新构建。源库不可访问时显示失败，不丢弃已有投影。UI 展示频次前 100 项及最近 50 个完成词；已标记但已被退格删除的词仍可在标记列表中找到。

## 验证

独立临时 SQLite 数据库验证了分词、数字别名、退格纠错、跨词回退、多分隔符、重启增量、摘要丢失重建、人工标记保留、事务失败回滚和源日志替换。真实 WPF 控件及完整 Dashboard 在深浅主题下离屏渲染，赞踩命令与绑定检查通过。性能部分在真实库的临时副本上实测：35.9 万条原始记录、跨度 14 天，冷缓存自动路径 2.7 秒（只回放窗口内的 4.1 万条，跳过 31.8 万条）且本进程 CPU 仅 0.86 秒，人工全量重建 25.8 秒、CPU 6.1 秒，追平后再刷新 33 毫秒不重建列表。测试未使用或修改真实用户数据库。
